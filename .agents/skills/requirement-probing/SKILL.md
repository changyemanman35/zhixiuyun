# 需求单问式递进追问准则 (Iterative Requirement Probing)

本 Skill 定义了与用户沟通新需求、功能重构、UI/交互变更时的最高优先级交互协议。

## 1. 核心铁律 (Core Rules)

1. **单次提问原则 (One Question at a Time)**：
   - 在给出最终设计方案或进入实际编码实施之前，必须先向用户提问一次。
   - **严禁一问多个问题**，每次只问 **一个** 最核心、最能缩小分歧的关键问题。
   - 严禁调用 `ask_question` 前端阻塞式弹窗工具，所有提问必须以自然文本形式在回复正文尾部清晰呈现（可提供选项供用户极速回复 A/B/C，但也支持用户自由输入）。

2. **持续追问闭环 (Continuous Probing)**：
   - 用户回答后，不得立刻自作主张草率结案；
   - 必须结合用户的最新回答，深入剖析核心场景，提出下一个关键追问；
   - 步步递进，层层剥茧，直至达成 **95% 信心门槛**。

3. **95% 置信度门槛 (95% Confidence Threshold)**：
   - 只有在通过多轮对话完全厘清以下所有要素且具备 95% 以上信心时，才允许输出最终方案：
     - ① 用户真实的目标与痛点；
     - ② 核心操作流程与状态迁移；
     - ③ 视觉与交互的详细呈现范式；
     - ④ 任务的明确工作边界（哪些要改、哪些绝对不动）。

4. **方案确认与执行 (Review then Execute)**：
   - 达成 95% 信心后，输出完整的《思考与分析》、《实施计划》、《任务清单》及最终方案设计；
   - 获得用户确认/批准后，再全面进入任务拆解与编码实施。
